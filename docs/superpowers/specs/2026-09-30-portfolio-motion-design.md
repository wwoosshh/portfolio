# 포트폴리오 v2 설계: 스크롤 연출과 대표작 시연

작성 2026-09-30. 대상 저장소 `wwoosshh/portfolio`, 기준 커밋 `32bea57`(v1 머지).

## 1. 배경과 목표

v1은 검증된 콘텐츠를 담았습니다. 그러나 사용자는 v1이 "하이퍼링크로 쓴 단일 HTML과 다를 게 없는 정보 나열"이라고 평가했습니다. 포트폴리오는 나를 소개하는 동시에 **어디까지 구현할 수 있는지 보여 주는 첫인상**이어야 합니다. v2는 같은 콘텐츠를 **발표처럼 연출된 인터랙티브 사이트**로 다시 보여 줍니다.

성공 기준은 다음과 같습니다.

1. 홈을 스크롤하면 발표 자료처럼 장면이 차례로 펼쳐진다.
2. 대표작 4개(Entail, torch.compile 퍼저, 글 언어, inversa-bench)는 직접 만져 볼 수 있는 시연으로 보여 준다.
3. 시연과 연출에 쓰는 값은 모두 실제 출력과 실제 수치이며, 출처가 기록되어 있다(v1의 근거 원칙 유지).
4. 자바스크립트가 없거나 움직임을 줄인 사용자에게도 모든 내용이 보인다.
5. 인쇄/PDF(공개용·제출용)는 v1처럼 정적이고 A4 4장 이하다.

## 2. 확정한 결정

| 항목 | 결정 |
|---|---|
| 발표 방식 | 자유 스크롤 + 스크롤에 맞춘 장면 연출. 별도의 발표 모드는 만들지 않는다 |
| 인터랙션 | 사이트 전체에 기본 연출을 두고, 대표작 4개는 직접 만지는 시연으로 만든다 |
| 시연 위치 | 홈 스토리 안에 둔다(고정 장면). 상세 페이지 상단에도 같은 시연을 버튼 진행 방식으로 넣는다 |
| 분위기 | 밝은 에디토리얼 + 설계도. 바탕은 종이색이고, 다이어그램과 시연 장면에만 모눈 패널을 쓴다 |

### 4.2 글꼴

- 한글과 본문은 Pretendard를 씁니다. 히어로와 장 제목은 800 굵기로 `clamp(40px, 6vw, 88px)` 크기를 씁니다.
- 코드, 데이터, 라벨은 JetBrains Mono를 씁니다. 모노 글꼴 안의 한글은 Pretendard로 대체합니다(v1과 같음).
- 제목은 어절 단위로 나눠 차례로 등장시킵니다(SplitText).

### 4.3 유지하는 규칙

- 그림자를 쓰지 않습니다. 구분은 선, 배경색, 모눈으로 합니다.
- 모서리는 `--r-sm` 6px, `--r-md` 10px, 그리고 원형 점(50%)만 씁니다.

### 4.4 움직임

기본 움직임은 절제해서 씁니다. 종류는 등장(12~24px 올라오며 나타남), 선 그리기, 숫자 변화, 형광펜 긋기, 상태 색 전환 다섯 가지입니다.

강조 움직임은 정해진 지점에서만 씁니다.

| 움직임 | 쓰는 곳 |
|---|---|
| 3D로 뒤집히는 전환 | 1장·2장 간지 |
| 튕기며 자리 잡기 | 핵심 성과 숫자 |
| 흔들림 | 히어로와 퍼저에서 불일치가 잡히는 순간 |
| 회전하며 날아와 조립 | 글 언어의 토큰 → 구문 트리 |
| 기울며 넘어가는 슬라이드 | 2장 가로 구간 |
| 마우스를 따라 기울기 | 프로젝트 카드(그림자 없이) |

움직임 토큰은 CSS 사용자 정의 속성과 `src/motion/tokens.ts`에 같은 값으로 둡니다.

- 속도: `--dur-fast` 200ms, `--dur-base` 400ms, `--dur-slow` 800ms
- 곡선: `--ease-out` `cubic-bezier(.2,.8,.2,1)`, `--ease-in-out` `cubic-bezier(.7,0,.3,1)`, 튕김용 `--ease-back` `cubic-bezier(.34,1.56,.64,1)`

스크롤 연동(scrub)은 고정 장면에서만 씁니다. 나머지는 화면에 들어올 때 한 번 재생합니다. 움직일 수 있는 속성은 transform, 투명도, SVG 선 그리기뿐이고, 레이아웃을 바꾸는 속성은 움직이지 않습니다.

## 5. 기술 구조

### 5.1 점진적 향상

- 모든 장면은 Astro가 HTML로 미리 그립니다. 자바스크립트 없이도 최종 상태의 내용이 전부 보입니다.
- `<head>`의 짧은 인라인 스크립트가 첫 렌더링 전에 `html`에 클래스를 붙입니다. 자바스크립트가 켜지면 `js`를 붙이고, 움직임을 허용하면 `motion`을 추가로 붙입니다.
- 등장 전 상태로 숨기는 CSS는 `.js.motion` 아래에서만 적용합니다. 스크립트가 실패하면 3초 뒤 `motion` 클래스를 떼어 내용이 보이게 합니다.

### 5.2 장면 시스템

- 장면 하나는 `src/components/scenes/<Name>.astro`(마크업)와 `src/motion/scenes/<name>.ts`(연출)의 쌍입니다. 연출 모듈은 `setup(root, ctx) => cleanup`을 내보냅니다.
- `src/motion/registry.ts`가 `[data-scene]` 요소를 찾아 화면 근처에 오면 해당 모듈을 불러옵니다. 모듈은 동적 import로 불러옵니다.
- `gsap.matchMedia()`로 세 경우를 나눕니다.

  | 경우 | 동작 |
  |---|---|
  | 데스크톱(768px 이상, 움직임 허용) | 고정과 스크롤 연동 |
  | 모바일(768px 미만, 움직임 허용) | 고정 없이 화면에 들어올 때 재생 |
  | 움직임 줄임(`prefers-reduced-motion: reduce`) | 최종 상태로 즉시 표시. 시연은 버튼으로 진행 |

- 상단 바의 진행 막대와 목차 강조는 ScrollTrigger로 계산합니다. "건너뛰기"는 해당 장면의 ScrollTrigger 끝 위치로 이동합니다.
- 2장 가로 구간은 고정한 컨테이너를 스크롤 진행에 따라 가로로 옮깁니다. 모바일과 움직임 줄임에서는 세로로 쌓습니다.
- GSAP과 플러그인 등록은 `src/motion/gsap.ts` 한 곳에서만 합니다. 버전은 정확히 고정합니다.

### 5.3 시연 구조

시연 하나는 `src/demos/<name>/` 아래에 다음 파일로 구성합니다.

| 파일 | 역할 |
|---|---|
| `data.json` | 실제 출력과 수치, 출처(§7) |
| `model.ts` | 순수 상태 머신. 단계 목록, 전이, 조작에 따른 화면 데이터. DOM에 의존하지 않음 |
| `view.ts` | 모델 상태를 DOM에 반영하고 GSAP 연출을 붙임 |
| `Demo.astro` | 자바스크립트 없이도 읽히는 최종 상태 마크업과 조작 요소 |

모드는 두 가지입니다.

- 홈은 스크롤 모드입니다. 고정 장면의 스크롤 진행이 "안내 단계"를 넘기고, 마지막 단계에 도달하면 조작 요소가 활성화됩니다.
- 상세 페이지는 버튼 모드입니다. "다음 단계" 버튼으로 진행하고, 화면에 들어오면 자동으로 한 번 재생합니다.

접근성 요건은 다음과 같습니다.

- 모든 조작은 키보드로 할 수 있습니다(버튼, 탭은 `role="tablist"`, 스위치는 `role="switch"`).
- 단계가 바뀌면 `aria-live="polite"` 영역에 단계 설명을 적습니다.

### 5.4 성능 예산

| 항목 | 목표 |
|---|---|
| 홈의 자바스크립트 합계(압축 기준) | 100KB 이하(GSAP과 플러그인 약 50KB, 시연 약 30KB) |

## 6. 장면과 시연 상세

### 6.1 Entail — 설정이 엔진까지 도달했는가

안내 단계는 다음 순서로 진행합니다.

1. `config.json`이 선언한 RoPE 설정이 보입니다. 값은 실제 모델 설정 파일에서 확인한 것만 씁니다.
2. vLLM 실행 옵션으로 `rope_scaling`을 넘기는 경로가 그려집니다.
3. `rope_theta`가 사라지면서 경로가 빨갛게 끊기고 base 10000으로 돌아갑니다.
4. GSM8K 정답 수가 379에서 273으로 떨어집니다.
5. Entail이 첫 토큰 전에 값을 바로잡아 376으로 돌아옵니다.
6. 인기 LLM 180개 중 64개가 영향을 받는다는 막대가 나옵니다.

조작은 "Entail 끔/켬" 스위치 하나입니다. 경로 색과 숫자(273 ↔ 376)가 바뀌고, 기준선 379는 계속 표시합니다. 출처는 Entail README 고정 링크(v1과 같은 SHA)와 vLLM #58675 본문입니다.

### 6.2 퍼저 — eager와 compile이 갈라지는 순간

탭은 실제 이슈 5개입니다: #198094, #198095, #198101, #198102, #198131.

탭마다 안내 단계는 다음 순서로 진행합니다.

1. 이슈 본문의 재현 코드가 한 줄씩 나타납니다.
2. eager 결과가 나옵니다.
3. compile 결과가 나옵니다.
4. 오라클이 반환값, 입력의 최종 상태, 별칭 관계 중 무엇이 달랐는지 표시합니다.
5. 불일치가 흔들리며 "오류 없음 · 값만 다름" 표시가 붙습니다.

조작은 탭 전환, 다시 실행, 텐서 칸에 마우스를 올려 값 비교하기입니다. 결과값은 이슈 본문에 적힌 그대로 쓰고, 실행 환경(torch 버전)을 함께 표시합니다. 약 21,000개·45분, 7계열, 이슈 6건(조용한 오답 5건, 크래시 1건) 같은 수치는 옆에 둡니다.

### 6.3 글 언어 — 한국어 코드가 기계어가 되기까지

예제 3개는 저장소의 테스트·예제에서 다음 기준으로 고릅니다.

- ① 한 줄을 출력하는 가장 작은 프로그램
- ② 함수를 정의하고 호출하는 프로그램
- ③ 조사가 맞지 않아 컴파일이 거부되는 D-30 예제

안내 단계는 다음 순서로 진행합니다.

1. 소스 코드가 보입니다.
2. 토큰으로 나뉘고 조사가 강조됩니다.
3. 토큰이 날아와 구문 트리로 조립됩니다.
4. IR이 나옵니다.
5. x86-64 바이트가 나옵니다.
6. 1·2·3세대 컴파일러 출력의 해시가 같아지는 자체 호스팅 장면으로 끝납니다.

조작은 예제 선택과, 조사를 바꿔 실제 컴파일 오류 메시지를 보는 것입니다. 데이터는 공개 저장소의 참조 컴파일러를 커밋 `e566d18`에서 실제로 실행해 덤프로 추출합니다. 추출 스크립트는 `scripts/demo-data/`에 두고, 화면에는 "실제 컴파일러 출력(e566d18)"이라고 표시합니다.

### 6.4 inversa-bench — 답에서 문제로, 그리고 +0.93

안내 단계는 다음 순서로 진행합니다.

1. 목표 답이 주어집니다.
2. 모델이 지은 실제 방정식이 나옵니다(저장소의 결과 기록에서 가져옴).
3. sympy가 풀어 "유일한 실근 = 목표"이면 통과시킵니다.
4. 허용 채점에서는 `x = 목표`를 그대로 써도 통과한다는 한계를 함께 보여 줍니다.
5. 모델 13개 산점도(구성 점수 × AIME)와 Spearman +0.93(95% CI +0.65~+1.0)이 나옵니다.

조작은 점에 마우스나 키보드 포커스를 두어 모델명과 값을 보는 것입니다. 출처는 커밋 `6f100b7`의 리더보드 JSON과 논문 표입니다.

### 6.5 2장의 움직이는 도면

이 구간에는 조작이 없고 연출만 있습니다.

- asahi: 디스코드 → 봇 → 허브 → 워커로 권한이 좁아지는 구조
- 바른오더: 고객 관리 조회 쿼리 4N+3 → 7
- 맛집큐브: 홈 초기 요청 4 → 1
- nogada: 버전 비교와 최대 3회 시도로 동시 갱신 유실 방지

수치와 사실은 v1 콘텐츠에서 검증한 것만 씁니다.

## 7. 데이터와 출처 규칙

- 시연 데이터 파일은 모두 Zod 스키마(`src/lib/demo-schema.ts`)를 통과해야 합니다.
- 필수 필드는 다음과 같습니다.
  - `sources[]`: 항목마다 `url`(http(s)), 해당하면 `sha`(40자리 16진수), `lines`
  - `extractedBy`: 추출 명령 또는 스크립트 경로
  - `verifiedAt`: 날짜
- 원본에 없는 값은 화면에 넣지 않습니다. 히어로의 "통과" 흐름은 개수만 보여 주고, 개별 값은 만들어 넣지 않습니다.
- 추출 스크립트는 저장소에 두어 다시 실행할 수 있게 합니다. 비공개 저장소의 내용은 추출하지 않습니다.
- v1의 규칙은 그대로 유지합니다.
  - 프로젝트 핵심 수치와 홈 핵심 성과에는 근거가 있어야 합니다.
  - 줄 번호 링크는 커밋 SHA로 고정합니다.
  - 전화번호와 개인 이메일은 저장소와 공개 PDF에 넣지 않습니다.

## 9. 테스트와 품질

**단위(Vitest)**

- 시연 상태 머신: 단계 순서, 전이, 조작 결과(예: Entail을 켜면 376)
- 시연 데이터 스키마와 출처 필수 필드
- 장면 등록기의 분기
- 개정된 디자인 규칙

**E2E(Playwright)**

- 자바스크립트 없음과 움직임 줄임 경로:
  - 모든 내용이 보이고 고정 장면이 없다.
  - v1의 제목 계층·링크·가로 넘침·근거 검사가 통과한다.
- 움직임 켬 경로:
  - 콘솔 오류가 없다.
  - 목차 이동과 건너뛰기가 작동한다.
  - 시연 4개의 조작이 작동한다.
- 모바일 폭(390px): 고정이 없고 가로로 넘치지 않는다.
- 인쇄/PDF: 4장 이하이고 전화번호가 없다(v1과 같음).

**성능**

- 빌드된 자바스크립트 크기가 예산 안에 있는지 검사합니다.
- 스크롤 중 CLS를 측정합니다(PerformanceObserver).

**사람 확인**

장면마다 주요 순간을 스크린샷으로 찍어 사람이 확인합니다. 움직임은 픽셀 비교 테스트가 불안정하므로 자동 비교는 하지 않습니다.

**품질 기준**

- 키보드만으로 모든 조작이 가능하고, 포커스가 보인다.
- 색 대비는 4.5:1 이상이다.
- 성능 예산(§5.4)을 지킨다.
