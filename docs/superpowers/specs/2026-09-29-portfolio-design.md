## 1. 목적과 범위

**목적:** 취업(서류·면접)용 포트폴리오. 웹사이트와 PDF를 같은 데이터로 만든다. 언어는 한국어다.

**대표 분야(간판):** "정확성을 검증하는 AI/ML 시스템 엔지니어". 최종 문구는 콘텐츠 작업에서 확정한다.

**독자와 읽는 방식**

| 독자 | 읽는 방식 | 필요한 것 |
|---|---|---|
| 서류 심사자 | 1~2분 안에 훑어봄 | 첫 화면에서 정체성, 핵심 성과, 경력, 연락처가 보여야 함 |
| 기술 면접관 | 대표작을 깊게 봄 | 문제 → 접근 → 결과, 그리고 PR·코드·CI 같은 근거로 바로 이동 |

**성공 기준**
1. 첫 화면(데스크톱 1280px 기준 스크롤 없이)에서 이름, 대표 분야, 소개, 연락 수단이 보이고, 한 번 스크롤하면 핵심 성과가 보인다.
2. 화면에 나오는 모든 수치에 근거 링크가 있고, 빌드가 이를 강제한다.
3. PDF(A4, 4장 이하)가 웹과 같은 데이터에서 생성된다.
4. 폭 390·834·1280px에서 가로 스크롤이 없고, 콘솔 에러가 0이다.
5. 저장소에 비공개 조사 자료나 비밀정보가 없다.

**범위 밖 (후속 작업)**
- 개인 PC·리포의 보안 조치
- 꺼진 백엔드 재가동, 시연 영상 제작
- 각 프로젝트 리포의 README·이름·LICENSE 정리
- 영어판, 다크 모드, 직무별 버전(태그 필드만 미리 둔다), 개인 도메인, 방문자 분석

## 3. 정보 구조

### 3.1 홈 (`/`)

한 페이지에 아래 순서로 배치한다.

1. **소개:** 이름, 한 줄 정체성, 2~3문장 소개, GitHub·이메일·PDF 버튼
2. **핵심 성과 3~4개:** 각 성과에 상태와 근거 링크를 붙인다.
3. **대표 프로젝트 (AI/ML 시스템과 컴파일러):** Entail, torch.compile 정합성 퍼저 + PyTorch 수정, 글(Geul) 언어, inversa-bench
4. **AI 에이전트·제품:** asahi, 바른오더, 맛집큐브, nogada-rpg(비공개 저장소)
5. **경력·활동:** 이루리랩스(패스드림 AI, 글로만), 코딩 동아리 세미콜론, 학력, 병역
6. **일하는 방식:** AI 협업 원칙과 근거(설계 문서 → 계획 → TDD 흐름, ADR, 교차 검증 기록)
7. **그 밖의 프로젝트:** GeulOS, Connect 메신저, monney는 카드(`tier: card`)로 보여 준다. 아래 후보 중 최대 6개를 한 줄(`tier: line`)로 보여 주며, 콘텐츠 작업에서 사용자와 함께 고른다.
   - 후보: semicollon.com 동아리 홈페이지, CodingInfo, GitSpace, 여기모여(1111), novel-worker, Board + BoardAPI, ChessGame, restaurant_android, BattleArena
   - 공개 링크가 없는 로컬 전용 작업은 넣지 않는다.
8. **기술 스택:** 프로젝트로 증명되는 기술만 넣고, 해당 프로젝트로 링크한다.
9. **연락처**

### 3.2 상세 페이지 (`/projects/<slug>`)

3·4번 섹션의 대표작 8개(`tier: featured`)에만 만든다. 구성 순서는 다음과 같다.

1. 요약: 기간, 역할, 저장소 공개 여부, 상태, 스택
2. 핵심 수치: 데이터에서 자동으로 그리고, 확인 날짜를 붙인다.
3. 본문(MDX): 문제 → 접근 → 결과 → 주요 결정 → 한계와 다음 단계 → AI 협업 방식
4. 외부 PR·이슈: 해당 프로젝트에 연결된 것이 있을 때만
5. 링크 목록: 데이터에서 자동으로 그린다.

숫자를 먼저 보여 주는 이유는 훑어보는 독자가 본문을 읽기 전에 결과부터 확인할 수 있게 하기 위해서다. 본문의 "결과"에는 숫자의 해석을 쓴다.

외부 기여(PR·이슈)는 관련 상세 페이지에 목록으로 보여 준다. PyTorch PR·이슈는 torch.compile 정합성 퍼저 페이지에, vLLM·SGLang·ComfyUI 이슈는 Entail 페이지에 둔다. 프로젝트와 기여를 잇는 필드는 `contributions[].project`(4.4)다. 상세 페이지가 없는 PDF에는 전체 목록을 따로 싣는다(6장).

### 3.3 PDF 원본 (`/print`)

같은 데이터로 만든 A4 인쇄용 페이지다. 검색 엔진 색인을 막는다(`noindex`). 자세한 내용은 6장에 있다.

### 3.4 넣지 않는 것

학습·실습 수준 프로젝트, 공개에 부적합한 프로젝트, 취득하지 않은 자격증, 회사 코드·화면·내부 문서.

## 4. 콘텐츠 모델

### 4.1 파일

| 파일 | 내용 |
|---|---|
| `src/content/projects/<slug>.mdx` | 프로젝트 하나에 파일 하나. 앞부분(frontmatter)에 데이터, 본문에 케이스 스터디 |
| `src/data/profile.ts` | 이름, 대표 분야, 소개, 연락처, 학력, 병역, 경력, 활동, 일하는 방식, 기술 스택 |
| `src/data/contributions.ts` | 외부 PR·이슈 목록과 확인 날짜 |

### 4.2 프로젝트 스키마

| 필드 | 형식 | 규칙 |
|---|---|---|
| `title` | 문자열 | 필수 |
| `tagline` | 문자열 | 필수. 한 문장 |
| `tier` | `featured` \| `card` \| `line` | 필수. `featured`는 대표작(상세 페이지 있음), `card`는 카드만, `line`은 한 줄 목록 |
| `track` | `ml` \| `agent` \| `product` \| `other` | 필수. `featured`는 `ml`이면 홈 3번 섹션, `agent`·`product`면 4번 섹션에 놓인다. `featured`는 `other`일 수 없다 |
| `order` | 숫자 | 같은 섹션 안 정렬 순서 |
| `period` | `{ start: 'YYYY-MM', end?: 'YYYY-MM' }` | `end`가 없으면 "진행 중" |
| `role` | 문자열 | 예: "1인 개발 · AI 코딩 에이전트 협업" |
| `stack` | 문자열 배열 | 필수 |
| `repo` | `{ visibility: 'public', url }` \| `{ visibility: 'private' }` | 비공개면 URL을 받지 않고 "비공개 저장소"로 표시 |
| `deployment` | `{ state: 'live', url }` \| `{ state: 'down', url?, video?, screenshot? }` \| `{ state: 'none' }` | `live`만 "운영 중"으로 표시. `down`은 "○ 서버 중지"와 영상·스크린샷 |
| `asOf` | 날짜 | 필수. 수치를 확인한 날짜 |
| `brief` | `{ problem, approach, result }` | `tier: featured`면 필수. 각 한두 문장. PDF와 요약에 쓴다 |
| `metrics` | `{ label, value, evidence, status? }` 배열 | `evidence`는 필수다. 공개 URL이거나, **비공개 저장소 프로젝트에 한해** `{ private: true, note }`("비공개 저장소 · 면접에서 화면 공유로 시연" 등)를 쓸 수 있다. `tier: featured`면 1개 이상. `line`은 수치를 화면에 그리지 않는다 |
| `links` | `{ label, url, kind }` 배열 | `kind`는 `repo`, `pr`, `issue`, `package`, `site`, `video`, `doc`, `ci` 중 하나 |
| `aiCollab` | 문자열 | 필수. 모든 프로젝트에 AI 협업 방식을 적는다 |
| `tags` | 문자열 배열 | 직무별 버전을 위해 미리 둔다. 지금은 화면에 쓰지 않는다 |
| `cover` | 이미지 | 선택 |

`metrics[].status`는 `ok`, `wait`, `off` 중 하나이고, 5.3의 상태 표시와 대응한다. 값이 없으면 상태 기호 없이 표시한다.

### 4.3 스키마가 막는 실수

- 근거 링크가 없는 수치가 있으면 빌드가 실패한다.
- 비공개 근거(`{ private: true }`)는 저장소가 비공개인 프로젝트에서만 허용한다. 공개 저장소 프로젝트는 반드시 공개 URL로 증명한다.
- 대표작에 `brief`가 없으면 빌드가 실패한다.
- 외부 PR·이슈는 상태(`open`, `merged`, `closed`)를 필수로 받아 화면에 그대로 보여 준다. 머지되지 않은 PR을 "기여"로 부풀릴 수 없다.
- `deployment.state`가 `down`인 프로젝트는 "운영 중"으로 표시될 수 없다.
- 비공개 저장소는 링크를 가질 수 없다.
- `aiCollab`이 빠진 프로젝트는 빌드가 실패한다.
- 기술 스택 항목은 실제로 존재하는 프로젝트 slug를 하나 이상 참조해야 한다.

### 4.4 profile·contributions 스키마 요점

**profile**
- `asOf`: 핵심 성과를 확인한 날짜
- `headline`: `{ mark, rest }`. `mark` 부분에 제목 형광펜을 칠한다.
- `highlights[]`: 핵심 성과 3~4개. 각각 `{ label, detail, status, statusText, evidence: URL }`이고 근거 URL은 필수다.
- `experience[]`: 조직, 제품, 기간, 역할, 근로 형태, 설명(bullet), `disclosure: 'text-only'`. 이 값이면 이미지와 링크를 그리지 않는다.
- `howIWork`: 원칙 목록과 근거 링크 목록
- `skills[]`: 이름과 `projects: slug[]`

**contributions**
- 항목: `{ repo, kind: 'pr' | 'issue', number, title, state: 'open' | 'merged' | 'closed', url, project: slug, labels?, note? }`
- `project`는 실제로 존재하는 `tier: featured` 프로젝트여야 한다(빌드 시 검사).
- 목록 전체에 확인 날짜 `asOf`를 붙인다.
- 상태 표시 규칙(자동 계산)

| 조건 | 표시 |
|---|---|
| PR `merged` | `✓ 머지됨` (ok) |
| PR `open` | `● 리뷰 중` (wait) |
| PR `closed` | `○ 닫힘` (off). `note`가 있으면 사유를 함께 표시 |
| 이슈 `open` + 라벨 `triaged` | `✓ 분류됨` (ok) |
| 이슈 `open`, 라벨 없음 | `● 열림` (wait) |
| 이슈 `closed` | `○ 닫힘` (off) |

### 4.5 상세 본문 템플릿

MDX 본문은 `## 문제`, `## 접근`, `## 결과`, `## 주요 결정`, `## 한계와 다음 단계`, `## AI 협업 방식` 순서로 쓴다. 결과의 수치 표와 링크 목록은 데이터에서 자동으로 그리고, 본문에는 해석만 적는다.

## 5. 디자인 시스템 (B안, 그림자 없음)

시안 기록은 저장소 밖 `C:\Portpolio\.superpowers\brainstorm\`에 있다.

### 5.1 원칙

1. **그림자 없음:** 구분은 1px 선과 배경색 차이로만 한다. 흐림, 그라데이션, 떠 보이는 효과는 쓰지 않는다.
2. **움직임 최소:** 마우스를 올리면 테두리 색만 진해진다. 이동·확대 효과와 등장 애니메이션은 없다.
3. **색은 의미에만:** 파랑은 링크와 포커스, 초록·주황·회색은 상태에만 쓴다. 장식은 제목 형광펜 하나뿐이다.
4. **같은 부품 반복:** 카드, 태그, 버튼, 상태 표시는 각각 한 가지 모양만 둔다.

### 5.2 토큰

| 분류 | 토큰 |
|---|---|
| 색 | `bg #fafaf9`, `surface #ffffff`, `line #e7e5e4`, `line-strong #d6d3d1`, `line-hover #a8a29e`, `text #1c1917`, `text-2 #57534e`, `text-3 #78716c`, `link #2563eb`, `ok #15803d`, `wait #b45309`, `off #78716c`, `mark #d9f99d` |
| 글꼴 | 본문·제목 Pretendard(npm `pretendard`, dynamic subset, 직접 호스팅). 라벨·상태·태그·코드 JetBrains Mono(npm `@fontsource/jetbrains-mono`) |
| 글자 크기 | display 36/800, h2 24/700, h3 18/700, body 16/400, small 14/400, mono 12/400 |
| 줄 간격·한글 | 본문 1.6~1.7, `word-break: keep-all` |
| 간격 | 4의 배수: 4, 8, 12, 16, 24, 32, 48, 64. 섹션 간격은 데스크톱 64, 모바일 48 |
| 모서리 | `r-sm 6px`(버튼·태그), `r-md 10px`(카드) |
| 테마 | 밝은 테마 하나. PDF도 같은 색을 쓴다 |
| 포커스 | `outline: 2px solid link; outline-offset: 2px` |

모든 글자색과 배경 조합은 WCAG AA(4.5:1)를 통과한다.

| `Button` | 고정폭 글꼴 12px, 1px `line-strong` 테두리, `r-sm`. 마우스를 올리면 테두리만 `line-hover`로 바뀜 |
| `Tag` | 고정폭 11px, `bg` 바탕, 1px `line` 테두리, `r-sm` |
| `Status` | 글자와 기호만 쓰고 배경은 없음. `✓` ok(머지·분류됨·통과·운영 중), `●` wait(리뷰 중·진행 중), `○` off(닫힘·서버 중지·보관) |
| `Card` | `surface` 바탕, 1px `line`, `r-md`, 패딩 16~20. 그림자 없음 |
| `MetricRow` + `Evidence` | 항목명, 고정폭 값, "근거 → 짧은 이름 ↗" 링크 |
| `SectionHeader` | `// 섹션명` 형식, 고정폭 12px, `text-3` |
| `Timeline` | 왼쪽 1px 선과 작은 점. 기간(고정폭)·제목·설명 |
| `ProjectCard` | 제목, 메타(기간·역할), 한 줄 설명, 태그, 근거 링크, "자세히 →" |

### 5.4 레이아웃

- 콘텐츠 최대 폭은 960px이고, 긴 본문은 680px로 제한한다.
- 카드 그리드는 768px 이상에서 2열, 그보다 좁으면 1열이다.
- 홈 첫 화면에는 사진을 넣지 않는다(선택 사항으로 나중에 추가할 수 있다).

## 6. PDF

- **원본:** `/print` 페이지. 웹과 같은 컴포넌트와 토큰을 쓰고, `@page { size: A4; margin: 16mm }`로 A4 세로를 만든다.
- **구성 (4장 이하)**
  1. 이름, 대표 분야, 소개, 연락처(이메일·GitHub·사이트 주소), 핵심 성과, 경력·활동·학력·병역, 일하는 방식 요약
  2. 대표 ML 프로젝트 4개 (각 반 페이지: 문제·접근·결과·근거)
  3. 에이전트·제품 4개 (각 1/4 페이지)
  4. 그 밖의 프로젝트, 기술 스택, 외부 기여 목록
- **링크:** 모든 근거 링크를 클릭할 수 있게 둔다. 인쇄해도 알아볼 수 있도록 `vllm#58675`처럼 짧은 이름으로 표시한다.
- **생성:** `npm run pdf`
  1. 사이트를 빌드한다.
  2. 미리보기 서버를 띄운다.
  3. Playwright Chromium으로 `page.pdf({ format: 'A4', printBackground: true, preferCSSPageSize: true })`를 실행한다.
  4. 결과를 `public/portfolio.pdf`로 저장한다.
  5. 사람이 확인한 뒤 커밋한다.
- **내려받기 파일명:** `우성현_포트폴리오.pdf` (`download` 속성)
- **공개용과 제출용**
  - 공개용 PDF(`public/portfolio.pdf`, 사이트에서 내려받기)에는 전화번호를 넣지 않는다.
  - 지원서 제출용 PDF는 `npm run pdf:private`로 만든다. 저장소 **밖**의 `C:\Portpolio\private\contact.json`에서 전화번호를 읽어, 렌더링한 인쇄 페이지의 빈 칸(`data-private-slot="phone"`)에만 끼워 넣는다. 결과도 저장소 밖 `C:\Portpolio\private\`에 저장한다.
  - 전화번호는 소스, 빌드 결과, 공개 PDF, 커밋 어디에도 들어가지 않는다.
- **검사:** 페이지 수가 4 이하인지, 글꼴이 임베드됐는지, 텍스트가 잘리지 않았는지 확인한다(PNG로 렌더링해 눈으로 확인).

## 9. 콘텐츠 작업 방식

- 문구는 비공개 조사 자료를 바탕으로 초안을 쓴다. 작성할 때 모든 수치를 원본(GitHub, PyPI, CI)에서 다시 확인하고 `asOf`를 갱신한다.
- 사용자에게 받은 입력(2026-09-29)
  - 공개 연락 이메일: 업무용 주소(사이트와 두 PDF 모두)
  - 전화번호: 제출용 PDF에만(6장)
  - 동아리 직책: 창립 회장
  - 실무 경력 표기: 개발 근로(청운대 취업연계 국가근로)
- 콘텐츠 검토 때 확인할 입력: 대표 분야 최종 문구, 동아리 활동 시작 시기, (선택) 사진
- 사용자가 전체 문구를 승인하기 전에는 공개 배포하지 않는다.
